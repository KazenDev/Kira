FLAG:
  response_format: { "type": "json_object" }

REGLAS OBLIGATORIAS (bugs conocidos de DeepSeek):
  1. La palabra "json" DEBE aparecer en el system prompt + un ejemplo
     del schema (si no, el modelo puede generar espacios en blanco
     hasta el limite de tokens -> parece "colgado")
  2. max_tokens generoso (200-300) para que NUNCA corte el JSON a la
     mitad (si corta, json.loads() explota)
  3. Primero SIN streaming: esperamos el JSON completo (1-3s, perfecto
     para el micro:bit que tarda ~2s en la transicion)

SCHEMA DE SALIDA (una sola bandeja con texto + emocion):
  {
    "emotion": "happy" | "sad" | "angry" | "surprised" | "neutral"
             | "fastidio" | "miedo" | "cansado" | "talk" | "loading" | "stop",
    "message": "el texto que Kira dice, en espanol rioplatense"
  }

  Python:
    - emotion -> comando serial al micro:bit (HAPPY, SAD, TALK...)
    - message -> lo que se muestra / se escucha

================================================================================
  TEMPERATURA POR EMOCION  (ESTADO EMOCIONAL PERSISTENTE)
================================================================================

IDEA: como en la vida real, cada emocion cambia como respondemos:
      estar enojado te hace predecible (corto y duro), estar feliz
      te hace creativo y expansivo. La temperatura se elige ANTES de
      cada llamada, segun la emocion ACTUAL de Kira (la que mando en
      su ultima respuesta). El modelo NO controla su propia
      temperatura: Python la elige por el estado emocional.

RANGO VALIDO DE LA API: temperature [0.0 - 2.0], default 1.0
  - Baja (0.0-0.5) = determinista, predecible, corto
  - Media (0.7-1.0) = balanceado
  - Alta (1.2-1.5) = creativo, impredecible, expresivo
  - NO usar temperature y top_p a la vez (DeepSeek lo desaconseja)

TABLA DEFINITIVA (basada en psicologia del habla + docs de temperatura):
  La temperatura controla diversidad y longitud implicita:
  - baja (0.2-0.5) = corto, repetitivo, predecible  (negativas)
  - media (0.7-1.0) = directo, natural              (neutra)
  - alta (1.2-1.4) = largo, variado, expresivo      (positivas)

  Feliz      😄  1.3   (mas palabras, vocabulario diverso -> temp alta)
  Triste     😢  0.6   (menos palabras, repeticion, auto-foco -> media-baja)
  Enojado    😠  0.3   (frases cortas, imperativos, vocabulario reducido -> MUY baja)
  Sorprendido😲  1.2   (exclamaciones espontaneas -> alta pero contenida)
  Neutral    😑  0.9   (directo pero natural -> media)
  Fastidio   😤  0.4   (cortante, trunca frases, monosilabos -> baja)
  Miedo      😨  0.5   (hesita, repite, fragmentado -> baja-media)
  Cansado    😪  0.4   (minimo esfuerzo, frases cortas -> baja)
  (talk / loading / stop heredan la emocion actual)
  (el Corazon ❤️ se elimino del proyecto: no se usa)

CAMBIO DINAMICO - TRANSICION SUAVE (RAMP):
  Cuando Kira cambia de emocion, la temperatura NO salta de golpe:
  Python la acerca en PASOS hasta el objetivo de la emocion nueva.
  Ejemplo: feliz(1.3) -> enojada(0.3):
    respuesta 1: 1.3   (sigue feliz)
    cambio a enojada -> rampa: 1.1, 0.9, 0.7, 0.5, 0.3
    (una respuesta por paso, o si el cambio es fuerte, 2 pasos por
     respuesta - ajustable en vivo en la feria)
  Por que: en la vida real no te enojas de golpe - la temperatura
  baja gradualmente igual que se te va calentando la sangre.
  Un enojado que sigue 1.3 un rato suena raro (muy creativo para
  estar furioso); un feliz que cae a 0.3 al instante se corta.

FLUJO EN PYTHON (resumen):
  1. estado = "happy" (inicial)
  2. antes de llamar: temperature = TABLA[estado]
  3. llamada a la API con system prompt + historial + json mode
  4. respuesta JSON: { emotion: NUEVA, message: TEXTO }
  5. Python: manda emotion al micro:bit por serial + muestra/habla TEXTO
  6. estado = NUEVA  -> la proxima respuesta usa la temperatura de esa
  7. repetir

NOTAS:
  - frequency_penalty / presence_penalty: DEPRECADOS en DeepSeek
    (se pueden mandar pero no hacen nada)
  - top_k: no soportado
  - Despues (fase 2): function calling para buscar en internet,
    con el patron de 2 pasos (tools primero, JSON al final)
